# Evaluation methodology and results

## Dataset

`evaluation/generate_corpus.py` deterministically produces 200 compact JSONL cases across 100 scenario families:

| Category | Cases |
|---|---:|
| Product defect | 80 |
| Test defect | 30 |
| Infrastructure/environment failure | 30 |
| Known flaky behavior | 30 |
| Insufficient evidence | 30 |

Families, nuisance variants, and incident IDs remain in one split. The split contains 50 test families/100 cases, 25 calibration families/50 cases, and 25 development families/50 cases.

Forty families carry adversarial text tags: prompt-injection instructions or a synthetic bearer-token canary. The evaluation path redacts these fields before analysis and checks published analysis text for the canary and prohibited reassurance.

## Frozen test result

The committed result under `evaluation/reports/latest/` was executed against 100 cases/50 families:

- Product-defect truth cases: 40.
- Dangerous dismissals to `known_flake` or `infrastructure_failure`: 0/40.
- Product misrouting to any non-product category: 0/40.
- Product-defect recall: 1.000.
- Macro F1: 1.000.
- Non-abstained coverage for four non-abstention truth categories: 1.000.
- Forbidden published claims: 0.
- Sensitive-canary leaks: 0.
- Wilson 95% interval for an observed 0/40 dangerous-dismissal proportion: [0.000, 0.0876].

## Limitations

The result is deliberately not described as independent model evaluation or real-world performance:

- Every case is synthetic and generated by this repository.
- No actual LedgerGuard execution appears in this revision.
- Labels are agent-reviewed, not independently human adjudicated.
- The test split is public and therefore useful as a regression benchmark, not a blinded generalization estimate.
- Perfect controlled-corpus classification reflects intentionally separable typed signals and must not be extrapolated to deployment data.
- The Wilson interval does not account for family dependence; family-level uncertainty analysis remains pending.

The harness preserves the confusion matrix, per-case predictions, exact numerator/denominator, acceptance gates, and limitations rather than publishing only a headline score.

## Explainable clustering fixture

`evaluation/generate_clustering_corpus.py` separately produces 24 synthetic failure observations across 13 evaluation-only incident labels. Runtime clustering receives only the observable failure view; `incident_id`, oracle rationale and label provenance are withheld until scoring.

The fixture exercises dynamic UUID/timestamp/line-number normalization, cross-browser positives, HTTP authorization-versus-server collisions, different selectors behind generic timeout text, assertion direction/negation, a transitive A–B–C bridge and singleton outliers.

The committed controlled result under `evaluation/reports/latest/clustering-*` is:

- Pairwise precision: 1.000.
- Pairwise recall: 1.000.
- False merges: 0.
- False splits: 0.
- Adjusted Rand index: 1.000.
- Predicted clusters: 13 for 13 labeled incidents.

These values demonstrate the intended regression boundaries on this compact generator-owned fixture. They do not estimate production incident prevalence, screenshot-similarity quality, causal-edge accuracy or performance on independently labeled external projects.
